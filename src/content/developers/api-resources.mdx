Use these endpoints to publish and maintain the things people join in Hive3: events, courses, content, quests and jobs. You can sync a catalog from another system, schedule events from a calendar, post jobs from an applicant tracker, or let an AI agent draft and publish for a community you help run. All five kinds share one set of operations, described here. Course and content fields, event scheduling and world booking, and quest credits have their own pages: [Courses and content](/developers/api-resources-content), [Events: slots and worlds](/developers/api-resources-events) and [Quests: credits and objectives](/developers/api-resources-quests). To enroll, RSVP, apply or review participants, see [Participation workflows](/developers/api-workflows).

API access needs a Honey Bee plan or above; see the [developer overview](/developers). The examples read the key from `HIVE_API_KEY`. Operations shown with one curl block follow the same pattern in JavaScript (`fetch`) and Python (`requests`) as the full examples. Some field names still say `community` or `person`; both identify accounts, and a "community" is an account that others join.

## Kinds and scopes

The path segment `{kind}` is one of `events`, `courses`, `content`, `quests` or `jobs`. Posts use the same shape on [their own page](/developers/api-posts).

| Operation | Scope | Also needed for a community |
|---|---|---|
| List, get | `resources:read` | `communities:read` |
| Create, update, archive | `resources:write` | `communities:write` |

For a community you manage, the key owner must currently be an owner, admin or moderator of it, and the key's account allowlist (if set) must include it; see [Managed accounts](/developers/api-authentication#managed-accounts). Reads return only resources owned by your account or by accounts you manage; other accounts' public resources return `404`. Use [Search](/developers/api-search) to find them.

## Shared behavior

- **Owner.** Create for your own account by omitting `owner` (or `{ "type": "person" }`). To create for a community, send `{ "owner": { "type": "community", "communityId": "account_456" } }` (an account ID or `@handle`). Any other `owner` value is ignored. `owner` is ignored on update.
- **Visibility.** `public` (default), `protected` (members only) or `private`; unknown values become `public`. A Worker Bee owning account can only publish `public` resources: a request that newly sets another value returns `403 forbidden` (`A Honey Bee subscription is required to make content members-only or private`), and one that newly sets a `subscriptionId` returns `403 forbidden` (`A Honey Bee subscription is required to sell subscriptions, tickets or paid access`). The owning account's plan decides, not the acting admin's. Values a resource already stores can stay after a downgrade.
- **Subscriptions.** `subscriptionId` ties access to one of the owning account's subscription plans. Moderators can only choose an existing plan of that account (`403 forbidden`, `Choose an existing subscription plan of this account`).
- **Title and description.** `title` (or `name`) is required on create (`400`, `Title is required`). `description` also accepts `shortDescription` and `body`.
- **Images and files.** URL fields (`imageUrl`, `heroImage`, `attachmentUrl`) take plain URLs. `*StorageId` fields (`imageStorageId`, `heroImageStorageId`, `attachmentStorageId`, `employerLogoStorageId`) take upload IDs from [Uploads](/developers/api-uploads) made by the same key owner. Image fields need an image upload; a bad ID returns `400 invalid_request` (`imageStorageId must be a valid storage ID`) or `404 not_found`.
- **Other fields.** For events, courses, content and quests the whole JSON body is kept in the response's `data` object, so unknown fields are stored as sent. Jobs keep only the fields listed below.
- **Server-owned fields.** The server sets `id`, `type`, `owner`, `createdAt`, `updatedAt` and `archivedAt`. Each kind also protects a few fields (event `metaverseTime`, `courseId`, `kind`, `officeHours` and `sessionKey`; quest `maxQuestDays`, `questCreditSource`, `questCreditId`) and ignores values you send for them.
- **Timestamps.** Resource timestamps in responses are epoch milliseconds. Schedule fields you send are ISO 8601 strings; events require an offset or `Z` ([Timestamps](/developers/api-conventions#timestamps)).
- **Updates.** `PATCH` is partial: omitted fields keep their value. Arrays you send (`eventSlots`, `lessons`, `objectives`, `sections`, `tags`, `badges`) replace the stored array.
- **Archiving.** `DELETE` archives; archived resources disappear from lists, reads and search and cannot be updated (`404`).

| Kind | Creates per day | Request size limit |
|---|---|---|
| `events` | 20 | 128 KiB |
| `courses` | 10 | 256 KiB |
| `content` | 50 | 256 KiB |
| `quests` | 30 | 128 KiB |
| `jobs` | 20 | 64 KiB |

All kinds allow 60 creates per minute, 120 updates per minute and 60 archives per minute per account, on top of the account's [600 requests per minute](/developers/api-conventions#rate-limits). A body above its size limit (measured on the serialized request) returns `400 invalid_request` (`<kind> payload is too large`), or `413` when the raw body is more than 4 KiB over it. Limited requests return `429 rate_limited` with `Retry-After`.

## List and read resources

<Endpoint method="GET" path="/api/v1/{kind}" scopes={["resources:read", "communities:read (managed accounts)"]}>

Lists active resources of one kind, newest first. Without filters you get your own resources, plus those of up to 25 communities you currently moderate when the key has `communities:read`. The example lists jobs.

| Name | In | Type | Required | Notes |
|---|---|---|---|---|
| `kind` | path | string | Yes | `events`, `courses`, `content`, `quests` or `jobs`. |
| `limit` | query | integer | No | 1 to 100, default 25. Zero or negative returns `400`. |
| `cursor` | query | string | No | The `page.nextCursor` of the previous page. |
| `communityId` | query | string | No | List one account's resources (ID or `@handle`). Needs `communities:read`. |
| `ownerType` | query | string | No | `person` or `community`; it does not filter by type. `community` without `communityId` returns an empty list. |

```bash
curl "https://app.hive3.tech/api/v1/jobs?limit=2" \
  -H "Authorization: Bearer $HIVE_API_KEY"
```

</Tab>

<Endpoint method="GET" path="/api/v1/{kind}/{id}" scopes={["resources:read", "communities:read (managed accounts)"]}>

Returns one active resource owned by your account or an account you manage. Anything else, including archived resources, returns `404 not_found` (`Resource not found`).

```bash
curl https://app.hive3.tech/api/v1/jobs/job_123 \
  -H "Authorization: Bearer $HIVE_API_KEY"
```

Returns `200` with the resource object.

</Endpoint>

## Create a resource

<Endpoint method="POST" path="/api/v1/{kind}" scopes={["resources:write", "communities:write (community owner)"]}>

Creates a resource and returns it. Send an `Idempotency-Key` header (up to 128 characters) to make retries safe: the same key with the same body returns the first `201` response without creating a second resource, and the same key with a different body or kind returns `409 conflict`. Only successful responses are remembered. Common body fields are below; each kind adds its own (see the field sections that follow). The example creates a job.

| Name | In | Type | Required | Notes |
|---|---|---|---|---|
| `kind` | path | string | Yes | `events`, `courses`, `content`, `quests` or `jobs`. |
| `title` | body | string | Yes | `name` is accepted as an alias. |
| `description` | body | string | No | Defaults to an empty string. |
| `visibility` | body | string | No | `public`, `protected`, `private`. |
| `subscriptionId` | body | string | No | One of the owning account's subscription plans. |
| `owner` | body | object | No | Owner selector. |
| `badges` | body | string array | No | Labels shown on the resource. |

<Tabs labels={["curl","JavaScript","Python"]}>
<Tab>

```bash
curl -X POST https://app.hive3.tech/api/v1/jobs \
  -H "Authorization: Bearer $HIVE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: job-community-manager-001" \
  -d '{"title":"Community Manager","description":"Grow and support our member community.","employerName":"Design Guild","employmentType":"full-time","location":"Remote"}'
```

</Tab>
<Tab>

```js
const res = await fetch("https://app.hive3.tech/api/v1/jobs", {

  headers: {
    Authorization: `Bearer ${process.env.HIVE_API_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": "job-community-manager-001",
  },
  body: JSON.stringify({
    title: "Community Manager",
    description: "Grow and support our member community.",
    employerName: "Design Guild",
    employmentType: "full-time",
    location: "Remote",
  }),
});
const { data } = await res.json();
```

</Tab>

```python
        "employerName": "Design Guild",
        "employmentType": "full-time",
        "location": "Remote",
    },

job = res.json()["data"]
```

```json

    "id": "job_123",
    "type": "job",
```

| Status | `code` | When |
|---|---|---|
| 400 | `invalid_request` | `Title is required`, malformed JSON, an invalid upload ID, a kind-specific rule, or a body over the size limit. |
| 403 | `insufficient_scope` | A community owner without `communities:write` (`requiredScopes`). |
| 403 | `forbidden` | The key does not include that account, your role is too low, or the Worker Bee rule applies. |
| 404 | `not_found` | Unknown owner account or upload. |
| 409 | `conflict` | `Idempotency-Key` reused with a different request. |
| 429 | `rate_limited` | A per-minute or per-day creation limit. |

</Endpoint>

## Update and archive

<Endpoint method="PATCH" path="/api/v1/{kind}/{id}" scopes={["resources:write", "communities:write (community-owned)"]}>

Partially updates a resource with the same field names as create (without `owner`). The stored owner decides who may edit; the key owner needs a live owner, admin or moderator role on a community-owned resource. Events and quests that have started return `409 conflict` and can no longer be edited.

```bash
curl -X PATCH https://app.hive3.tech/api/v1/jobs/job_123 \
  -H "Authorization: Bearer $HIVE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"location":"Remote (Europe)","payRangeMin":"60000","payRangeMax":"80000"}'
```

Returns `200` with the updated resource. Errors: `400` (a kind-specific rule), `403 forbidden` or `insufficient_scope`, `404 not_found` (unknown or archived), `409 conflict` (started event or quest).

</Endpoint>

<Endpoint method="DELETE" path="/api/v1/{kind}/{id}" scopes={["resources:write", "communities:write (community-owned)"]}>

Archives a resource; nothing is hard-deleted. Archiving an event that has not started also refunds the metaverse time it reserved. Events and quests that have started return `409 conflict` (`This event has started and can no longer be cancelled.`). Archiving a quest does not refund its quest credit.

```bash
curl -X DELETE https://app.hive3.tech/api/v1/jobs/job_123 \
  -H "Authorization: Bearer $HIVE_API_KEY"
```

Returns `200` with `{ "data": { "archived": true, "id": "job_123", "type": "job" } }`. Archiving an already archived resource also returns `200`, quests included, so a retry is safe.

</Endpoint>

## Job fields

Jobs keep only the fields below; others are dropped. Courses, content, events and quests have their own field lists on the pages linked at the end.

| Field | Type | Notes |
|---|---|---|
| `title` | string | Required. |
| `description` | string | Job text. |
| `employerName` | string | Default `Hive employer`. |
| `employmentType` | string | `full-time` (default), `part-time`, `contract` or `intern`. Other values fall back to the default on create and keep the stored value on update. |
| `location` | string | Default `Remote`. |
| `payRangeMin`, `payRangeMax` | string | Free text such as `"60000"`. Numbers are ignored. |
| `employerLogo` | string | Logo URL (`employerLogoUrl` and `imageUrl` also work). `employerLogoStorageId` or `imageStorageId` take an upload ID. |
| `attachmentUrl` | string | Link to a document (`documentUrl` also works). `attachmentStorageId` takes an upload ID. |
| `status` | string | Default `published`. |
| `visibility`, `subscriptionId`, `badges` | | As in [Shared behavior](#shared-behavior). `subscriptionID` also works. |

## Fields for the other kinds

Courses, content, events and quests take more fields than the common ones above:

- **Courses and content** have lessons, office hours, sections and tags. See [Courses and content](/developers/api-resources-content).
- **Events** take `eventSlots` (each with ISO 8601 `startsAt` and `endsAt`), `autoEnroll` (default `false`) and an optional `worldId`. See [Events: slots and worlds](/developers/api-resources-events).
- **Quests** need a `questCreditPlan` (`single` or `bundle`) that spends one quest credit, plus `objectives`, `startsAt` and `endsAt`. See [Quests: credits and objectives](/developers/api-resources-quests).
