Use these commands to publish events, courses, content, quests and jobs, and to run what happens around them: RSVPs, enrollments, attendance, quest evidence and job applications. All of them print JSON. Conventions such as exit codes, `--file` merging and `--account` are on the main [CLI command reference](/developers/cli-commands#how-to-read-this-reference).

These commands also exist in CLI version 0.3, so nothing on this page carries the (0.4+) marker. `hive3 worlds` and `--world` are new in 0.5 and marked (0.5+). The event type flags and `events list --location` are new in 0.7 and marked (0.7+).

## Common actions

`posts`, `events`, `courses`, `content`, `quests` and `jobs` share the same five actions. Replace `<kind>` with the family name.

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 <kind> list` | Lists items, newest first, archived items left out. | `--limit <n>`, `--cursor <cursor>`, `--owner-type <type>`, `--community-id <id>`; events also `--location <type>` (0.7+) | `resources:read` (`posts:read` for posts) |
| `hive3 <kind> get <id>` | Reads one item you can see. | None | `resources:read` (`posts:read`) |
| `hive3 <kind> create` | Creates an item. Prints the new item as JSON. | Fields, owner options and `--idempotency-key` below | `resources:write` (`posts:write`) |
| `hive3 <kind> update <id>` | Changes fields of an item. At least one field is required. | Fields below and `--file`; no owner options | `resources:write` (`posts:write`) |
| `hive3 <kind> archive <id>` | Archives the item; it is not deleted. | None | `resources:write` (`posts:write`) |

For an item owned by a community, add `communities:write` to the write scopes and `communities:read` to reads on other accounts, and you need a current role there.

| Field flag | Sets |
|---|---|
| `--title <text>` | `title` (required for everything except posts) |
| `--body <text>` | `body` (required for posts) |
| `--description <text>` | `description` |
| `--content-type <type>` | `contentType` (used by content) |
| `--image-url <url>` | `imageUrl` |
| `--visibility <value>` | `public`, `protected` or `private`. Anything other than public needs Honey Bee or above on the owning account. |
| `--world <world>` | Events only (0.5+): `worldId`, the 3D world to book for a metaverse event, as a world ID from [`hive3 worlds`](#worlds) or `default` for the owning account's default world. See [the default world](/developers/api-resources-events#the-default-world). |
| `--location <type>`, `--address`, `--meeting-url`, … | Events only (0.7+): the event type and its venue or meeting. See [Event type flags](#event-type-flags). |
| `--file <path>` | A JSON object with any other fields. See [payload files](/developers/cli-commands#payload-files). |

| Owner and list flag | What it does |
|---|---|
| `--owner-type <type>` | `person` or `community`. On `create` it picks who owns the new item. On `list` it only works together with `--community-id`; it is not a type filter. |
| `--community-id <id>` | The community's account ID. Required whenever `--owner-type` is `community`. |
| `--idempotency-key <key>` | Makes a retried `create` safe. See [idempotency](/developers/api-conventions#idempotency). |

`--account` is not supported on these commands; use `--owner-type community --community-id <account-id>` to create for an account you help run, after `hive3 capabilities` shows it.

Things to know before you create:

- **Events** need RSVP approval by default. Put `"autoEnroll": true` in the file to accept attendees automatically. `eventSlots` entries need ISO 8601 `startsAt` and `endsAt` with a `Z` or offset, and each end must come after its start. You can create 50 events per day, counted against your own account and shared with the app.
- **Event type.** Set where the event happens with `--location irl`, `virtual` or `metaverse` and the matching [event type flags](#event-type-flags), or `location`, `venue`, `meeting` and `checkInMode` in the file. A Zoom, Meet or Teams link goes in `--meeting-url` of a `virtual` event, never in a slot link or an in-person address.
- **World events.** Without `--world` an event is not in a 3D world; never add it to an online or in-person event. When the user names a venue (for example "the Dome", "Night Lounge" or "our own world"), run [`hive3 worlds`](#worlds), match the name and pass that world's `id` with `--world <id>`. If the named world isn't listed, it can't be booked for that account: say so rather than booking another one. `--world default` books the owning account's default world (the one listed with `isDefault: true`): Swarm's default shared world chosen on the dashboard, Honey Bee's default shared world (Hive3 Dome unless another is set), or a Royal Hive account's own world. Use it only when no venue is named, and report which world it booked. Worker Bee accounts, and Royal Hive accounts whose world isn't set up yet, get `400` and nothing is created. A world event has exactly one slot, may spend metaverse time, and returns `409 conflict` when the slot is already booked. See [Book a world](/developers/api-resources-events#book-a-world).
- **Quests** need `questCreditPlan` (`single` for quests up to 7 days, `bundle` for up to 30) and spend one quest credit of the owning account. A credited quest needs a valid `startsAt`.
- Once an event or quest has started, `update` and `archive` return `409 conflict`.
- Plan rules apply as in the app. A Worker Bee account publishes publicly only and cannot attach subscriptions.

```json title="event.json"
{
  "title": "Portfolio night",
  "description": "Bring two projects for feedback.",
  "visibility": "public",
  "autoEnroll": true,
  "eventSlots": [
    { "startsAt": "2026-12-12T18:00:00Z", "endsAt": "2026-12-12T20:00:00Z" }
  ]
}
```

The file has no event type, so each example below adds one with flags. Putting `"location": "virtual"` and a `"meeting"` object in the file works the same way.

```bash title="Create, check and archive a virtual event"
hive3 events create --file event.json --location virtual \
  --meeting-url "https://us02web.zoom.us/j/123456" --idempotency-key portfolio-night-2026
hive3 events list --location virtual --limit 5
hive3 events archive "<event-id>"
```

```bash title="Book the world the user named"
hive3 worlds
hive3 events create --file event.json --location metaverse --world "<world-id>"
```

```bash title="Book the account's default world when no venue is named"
hive3 events create --file event.json --location metaverse --world default
hive3 events update "<event-id>" --world default
```

```bash title="Create for a community you manage"
hive3 capabilities
hive3 posts create --body "Moderator update" --owner-type community --community-id "<account-id>"
```

### Event type flags

`hive3 events create` and `update` (0.7+) take these flags. Flags override the same fields from `--file`. The CLI checks the values before sending and prints the API's message for a wrong one, for example `location must be irl, virtual or metaverse`.

| Flag | Sets | Notes |
|---|---|---|
| `--location <type>` | `location` | `irl` (in person), `virtual` or `metaverse`. Left out, the type follows from the other flags: `--world` means `metaverse`, meeting flags `virtual`, venue flags `irl`. |
| `--address <text>` | `venue.address` | In person. Public, up to 300 characters. A new address drops the old map details (city, place ID, coordinates). |
| `--venue-name <text>` | `venue.name` | In person, up to 120 characters. Needs an address. |
| `--venue-instructions <text>` | `venue.instructions` | In person: "getting there" notes, up to 1,000 characters. |
| `--check-in <mode>` | `checkInMode` | In person: `self` (one event QR code, the default) or `door` (a pass per guest, scanned at the door). |
| `--meeting-url <https-url>` | `meeting.url` | Virtual. Must be `https://`. |
| `--meeting-provider <provider>` | `meeting.provider` | Virtual: `zoom`, `google_meet`, `microsoft_teams`, `x_spaces`, `discord`, `youtube` or `other`. Left out, it is recognised from the link. |
| `--meeting-instructions <text>` | `meeting.instructions` | Virtual: passcode or dial-in details, up to 1,000 characters. |
| `--world <id\|default>` | `worldId` | Metaverse (0.5+). Only metaverse events can book a world. |

The CLI refuses these before anything is sent:

- Venue flags on an event that isn't in person: `--address, --venue-name, --venue-instructions and --check-in are for in-person events (--location irl)`.
- Meeting flags on an event that isn't virtual: `--meeting-url, --meeting-provider and --meeting-instructions are for virtual events (--location virtual)`.
- `--world` with `--location irl` or `virtual`: `Only metaverse events can book a world.`
- `--venue-name` or `--venue-instructions` when the event has no address: `In-person events need an address.`
- Text over its limit, for example `address must be 300 characters or fewer`.

On `update`, the type stays as it is unless a flag changes it (an event in a world stays `metaverse`). When you give any event type flag, the CLI reads the event first. If the type doesn't change, its current venue, meeting and check-in mode fill in whatever you leave out, so changing one detail keeps the others. A new `--address` drops the old city, place ID and coordinates. A new `--meeting-url` without `--meeting-provider` lets the API recognise the provider again. `update --location irl` or `virtual` on an event in a world moves it out of the world.

Output is the API's JSON, with `location`, `venue`, `meeting` and `checkInMode` (`null` unless `irl`). `meeting.url` and `meeting.instructions` appear only when you manage the event; other readers get only the provider. See [Event types](/developers/api-resources-events#event-types).

```bash title="In person, with door scanning"
hive3 events create --file event.json --title "Builders meetup" \
  --location irl --address "Torstraße 1, 10119 Berlin" --venue-name "Hive3 Space" \
  --venue-instructions "Ring the bell at the side door." --check-in door
```

```bash title="Virtual, then change the link"
hive3 events create --file event.json --title "Office hours" \
  --location virtual --meeting-url "https://meet.google.com/abc-defg-hij"
hive3 events update "<event-id>" --meeting-url "https://us02web.zoom.us/j/123456" --meeting-instructions "Passcode 4242"
```

```bash title="List only in-person events"
hive3 events list --location irl --limit 20
```

QR check-in (event codes, passes and the door scanner) and Google Calendar sync are only in the app, in the browser. There are no CLI commands for them. See [Check in at events](/create/check-in-at-events).

## Events

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 events participants <event-id>` | Lists RSVPs. Event managers only; the list includes primary email addresses. | None | `resources:read` |
| `hive3 events rsvp <event-id>` | Creates your RSVP, or withdraws it. | `--enroll <bool>` (`false` withdraws), `--file <path>` | `resources:write` |
| `hive3 events approve <event-id> <enrollment-id>` | Approves an RSVP. Needs the person's current access to the event. | None | `resources:write` |
| `hive3 events deny <event-id> <enrollment-id>` | Denies an RSVP. | None | `resources:write` |
| `hive3 events attendance <event-id> <enrollment-id>` | Records attendance. | `--attended <bool>`, `--file <path>` | `resources:write` |

RSVPs share the app's limits of 10 per minute and 100 per day. Attendance needs an approved RSVP on an event that is not archived; the first recorded time is kept, the attendee is notified, and clearing attendance (`--attended false`) is refused with `409 conflict`. Treat approving, denying and recording attendance as decisions that need a human check.

## Worlds

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 worlds` (0.5+) | Lists the 3D worlds the account's events may book, as `{ "worlds": [{ "id", "name", "kind", "isDefault" }], "needsDedicatedSetup" }`. | `--account <id-or-handle>` | `resources:read`; `communities:read` for another account |

The list matches what the app's event form offers: every shared world for Honey Bee, only the default shared world for Swarm, only its own world (`kind: "dedicated"`) for Royal Hive, and none for Worker Bee. `isDefault` marks the world `--world default` books. `needsDedicatedSetup: true` means a Royal Hive account must choose its world's design on the dashboard first. With `--account`, use the same account you pass to `--community-id`; you need a current owner, admin or moderator role there, and the key must include that account. See [List bookable worlds](/developers/api-resources-events#list-bookable-worlds).

```bash title="Find the Night Lounge ID for a community you manage"
hive3 worlds --account "<account-id>"
hive3 events create --file event.json --owner-type community --community-id "<account-id>" --world "<night-lounge-id>"
```

## Courses

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 courses enrollments <course-id>` | Lists enrollments. Course managers only. | None | `resources:read` |
| `hive3 courses enroll <course-id>` | Enrolls you, or withdraws. | `--enroll <bool>`, `--file <path>` | `resources:write` |
| `hive3 courses approve <course-id> <account-id>` | Approves a student's enrollment. `<account-id>` is the student's account ID. | None | `resources:write` |
| `hive3 courses deny <course-id> <account-id>` | Denies a student's enrollment. | None | `resources:write` |
| `hive3 courses complete <course-id> <lesson-id>` | Marks a lesson complete for you. | None | `resources:write` |

```json title="course.json"
{
  "title": "Intro to critique",
  "description": "Four short lessons.",
  "visibility": "public",
  "lessons": [
    { "id": "lesson-1", "title": "Give useful feedback" },
    { "id": "lesson-2", "title": "Receive feedback" }
  ]
}
```

## Content

`hive3 content` has only the [common actions](#common-actions), with `--content-type <type>` choosing the kind of content (the default is `article`).

```json title="content.json"
{
  "title": "Welcome guide",
  "description": "How this community works.",
  "contentType": "article",
  "visibility": "public"
}
```

## Quests

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 quests enrollments <quest-id>` | Lists enrollments. Quest managers only. | None | `resources:read` |
| `hive3 quests enroll <quest-id>` | Enrolls you, or withdraws. | `--enroll <bool>`, `--file <path>` | `resources:write` |
| `hive3 quests approve <quest-id> <enrollment-id>` | Approves an enrollment. | None | `resources:write` |
| `hive3 quests deny <quest-id> <enrollment-id>` | Denies an enrollment. | None | `resources:write` |
| `hive3 quests evidence list <quest-id>` | Lists submitted evidence. | `--status <status>`, for example `pending` | `resources:read` |
| `hive3 quests evidence submit <quest-id>` | Submits evidence for an objective. | `--objective-id <id>` (required), `--content <text>`, `--file <path>` | `resources:write` |
| `hive3 quests evidence approve <quest-id> <evidence-id>` | Approves evidence. | None | `resources:write` |
| `hive3 quests evidence deny <quest-id> <evidence-id>` | Denies evidence. | None | `resources:write` |

```json title="quest.json"
{
  "title": "Ship a portfolio page",
  "description": "Publish a page and share the link.",
  "questCreditPlan": "single",
  "startsAt": "2026-12-01T00:00:00Z",
  "endsAt": "2026-12-05T00:00:00Z",
  "objectives": [
    { "id": "objective-1", "type": "custom", "completionCriteria": "Submit a link", "evidenceType": "link" }
  ]
}
```

Objective types are those of the API, including `in_person_events_attended` (counted by QR check-in at an in-person event), `virtual_events_attended` and `metaverse_events_attended`. Each counts only events of its own type; with `targetEventId`, pick the type that matches the event's `location`. See [Event objectives](/developers/api-resources-quests#event-objectives).

To attach a file as evidence, upload it first and reference the returned upload ID. Use the `byteSize` and `contentType` of the file you uploaded.

```json title="evidence.json"
{
  "attachments": [
    { "storageId": "<upload-id>", "fileName": "proof.pdf", "contentType": "application/pdf", "byteSize": 100000 }
  ]
}
```

```bash title="Submit and review evidence"
hive3 upload ./proof.pdf --purpose document
hive3 quests evidence submit "<quest-id>" --objective-id objective-1 --content "https://proof.example" --file evidence.json
hive3 quests evidence list "<quest-id>" --status pending
hive3 quests evidence approve "<quest-id>" "<evidence-id>"
```

## Jobs

| Command | What it does | Flags | Scopes |
|---|---|---|---|
| `hive3 jobs apply <job-id>` | Applies to a job. The file must contain `resume`. | `--file <path>` (required) | `resources:write` |
| `hive3 jobs applications <job-id>` | Lists applications to a job. Job managers only; includes primary email addresses. | None | `resources:read` |
| `hive3 jobs applications` | Lists your own applications. | None | `resources:read` |
| `hive3 jobs status <application-id>` | Changes an application's status. | `--status <status>` (required): `pending`, `reviewed`, `accepted` or `rejected` | `resources:write` |

`resume` and the optional `coverLetter` each need `fileName`, `contentType` and a positive `byteSize`, plus a `storageId` from `hive3 upload --purpose document`.

```json title="application.json"
{
  "resume": { "storageId": "<upload-id>", "fileName": "resume.pdf", "contentType": "application/pdf", "byteSize": 124000 },
  "coverLetter": { "storageId": "<upload-id>", "fileName": "cover-letter.pdf", "contentType": "application/pdf", "byteSize": 84000 }
}
```

```json title="job.json"
{
  "title": "Community manager",
  "description": "Run weekly events and welcome new members.",
  "employerName": "Design Guild",
  "location": "Remote",
  "visibility": "public"
}
```

Participant, enrollment and application lists include each person's primary email address when you manage the resource. Keep that output out of logs, chats and prompts.
