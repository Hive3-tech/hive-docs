This page lists changes that can affect an integration: new endpoints and scopes, changed behavior, and corrections to earlier documentation. Each entry ends with what you need to do. The API stays at `/api/v1`: existing paths, scopes and field names are unchanged unless an entry says otherwise.

## November 2026: API and CLI 0.5.0

This update adds selling, payments, Stripe, private conversations and feedback to the API and the CLI, removes account deletion from both, makes ticket changes require confirmation, lets events go straight into an account's default 3D world, raises the daily event limit, and notifies members about new items. Items in the CLI pages marked "(0.5+)" need CLI 0.5.0 or later; run `hive3 update --check` to see your version.

### Breaking changes

- **Account deletion is browser only.** `POST /api/v1/account/deletion` (request) and `DELETE /api/v1/account/deletion` (cancel) are gone, the `account:destroy` scope can no longer be requested, and `hive3 account deletion cancel` is gone from the CLI. Delete an account, or cancel a pending deletion, in the Hive3 app. Keys of an account waiting to be deleted return `401 invalid_api_key` on every route. See [Data export and key revocation](/developers/api-account-data).
- **Ticket changes need confirmation and a request ID.** `PATCH /api/v1/tickets/{ticketId}` now requires `"confirmed": true` and a `requestId` or `Idempotency-Key`; without them it returns `400`. `hive3 tickets update` now requires `--yes`. Ticket currencies are `USD`, `EUR` and `GBP`. See [Tickets](/developers/api-tickets#confirmation-and-retries).
- **Data export needs every read scope.** `POST /api/v1/account/export` (`hive3 account export`) now needs `account:read`, `account:write`, `communities:read`, `resources:read`, `tickets:read`, `payments:read`, `feedback:read`, `ai:read` and `credentials:read`. A Full access key created after this update has them all. See [Export account data](/developers/api-account-data#export-account-data).
- **Login only talks to Hive3 by default.** `hive3 login` refuses API or app hosts other than `app.hive3.tech`, `staging.hive3.tech` and `localhost` unless you add `--allow-custom-api-url`. `--app-url` now defaults to the API URL's site. See [Login options](/developers/cli-authentication#login-options).

**What to do:** remove API or CLI calls that request or cancel account deletion; add `confirmed` and a request ID to ticket changes (`--yes` in the CLI); sign in again with Full access before exporting data; add `--allow-custom-api-url` only if you sign in against your own server.

### Selling and payments

- **Products and subscription plans.** `GET`/`POST /api/v1/products`, `GET`/`DELETE /api/v1/products/{productId}`, `GET`/`POST /api/v1/products/{productId}/plans`, `GET`/`PATCH`/`DELETE /api/v1/subscriptions/{planId}` and `POST .../activate` or `.../deactivate`; CLI `hive3 products` and `hive3 subscriptions`. See [Products, subscription plans and Stripe](/developers/api-selling).
- **Ticket creation.** `POST /api/v1/tickets`, `GET /api/v1/tickets/entities`, attaching with `PATCH` (`entityType`, `entityId`) and stopping sales with `DELETE`; CLI `hive3 tickets create`, `entities`, `attach` and `remove`. See [Tickets](/developers/api-tickets).
- **Stripe connection.** `/api/v1/payments/stripe/status`, `onboarding`, `refresh`, `dashboard`, `tax-setup` and `disconnect`; CLI `hive3 stripe`. Owners and admins only; identity and bank steps stay on Stripe's pages.
- **Payments.** Histories under `GET /api/v1/payments/…`, and `POST /api/v1/payments/preview` then `POST /api/v1/payments/operate` for checkouts, finalizing, subscription and membership cancel, resume, portal and plan changes, and ticket refund requests and decisions; CLI `hive3 payments`. Every action is previewed, then confirmed with the exact preview text; the payment itself happens in the buyer's browser, and nothing is retried automatically. See [Payments](/developers/api-payments).
- Seller and payment writes require `"confirmed": true` and a request ID (`--yes` in the CLI). Keys with payment scopes keep managing existing payments after a downgrade below Honey Bee.

### Conversations and feedback

- **Conversations.** `/api/v1/conversations` for your direct messages and message requests, and `/api/v1/community-messages` for community conversations: read, send, reply, edit, delete, react, mark read and accept; CLI `hive3 conversations`. Text only, always as the key owner. See [Conversations](/developers/api-conversations).
- **Feedback.** `/api/v1/feedback` to send bug reports and suggestions with up to four images and one video, list your tickets, read the conversation and reply; CLI `hive3 feedback`. See [Feedback and bug reports](/developers/api-feedback).

### Scopes and sign-in

- **Six new scopes.** `payments:read`, `payments:write`, `feedback:read` and `feedback:write` are part of Read access and Full access for new keys and CLI logins. `messages:read` and `messages:write` are never part of a preset: choose <UI>Private messaging access</UI> on the key page, or run `hive3 login --messages-access read|full` and tick the separate consent on the approval page. See [Scopes](/developers/api-authentication#scopes) and [Private messaging access](/developers/cli-authentication#private-messaging-access).
- **Approval page.** The request name now shows as **Name supplied by the requesting device**, with when and from which IP address the login started.
- **Reading resources.** `GET /api/v1/{kind}/{id}` also returns resources of other accounts that your account could see in the app, in the form a visitor sees. See [Events, courses, content, quests, jobs](/developers/api-resources).

**What to do:** existing keys do not gain the new scopes. Create a new key, or run `hive3 login` again, to use selling, payments or feedback, and add messaging only where you need it. After `hive3 update`, run `hive3 skill install --force` so your agent learns the new commands.

### Events and worlds

- **`"worldId": "default"`.** On `POST` and `PATCH /api/v1/events`, `default` books the owning account's default world without a world ID: Swarm's default shared world chosen on the dashboard, Honey Bee's default shared world (Hive3 Dome unless another is set), or a Royal Hive account's own world. A Worker Bee account, or a Royal Hive account whose world isn't set up yet, gets `400 invalid_request` and nothing is created or changed. The usual booking rules (one slot, attendee limit, overlaps, metaverse time) apply unchanged. Events sent without `worldId` stay outside any world, as before. See [The default world](/developers/api-resources-events#the-default-world).
- **CLI 0.5.0: `--world`.** `hive3 events create|update --world <world-id|default>` sets `worldId`. See [Resource commands](/developers/cli-commands-resources).
- **`GET /api/v1/worlds` and CLI 0.5.0 `hive3 worlds`.** Lists the worlds the owning account may book (`id`, `name`, `kind`, `isDefault`, plus `needsDedicatedSetup`), with `?account=` / `--account` for an account you help run; pass the named world's `id` as `worldId` instead of `default`. See [List bookable worlds](/developers/api-resources-events#list-bookable-worlds).
- **50 events per day.** The daily limit on creating events rose from 20 to 50 per account, shared with the app. The per-minute limit is unchanged. See [Rate limits](/developers/api-conventions#rate-limits).

**What to do:** to put events in the account's world without looking up a world ID, send `"worldId": "default"` (or `--world default`). If you throttled event creation to 20 a day, you can raise it to 50.

### Notifications

- New events, courses and quests created through the API or CLI (and in the app) now notify the owning account's accepted members in-app as `new_event`, `new_course` or `new_quest` notifications (existing mutes apply, and the creator is not notified). Members can also turn on a daily email digest of new items in Settings → Display & notifications.

**What to do:** if you read notifications through the API, handle the three new `type` values.

### Corrections to the documentation

- **Which worlds a plan can book.** Earlier pages said Honey Bee and Swarm accounts book the shared Hive3 Dome. Honey Bee can book any shared world (today Hive3 Dome and Night Lounge), Swarm books the shared world chosen as its default on the dashboard, Royal Hive books only its own world, and Worker Bee books none. Metaverse time and the 500-attendee limit apply to every shared world, not only the Dome. See [Book a world](/developers/api-resources-events#book-a-world).

**What to do:** nothing; the booking rules themselves did not change.

## October 27, 2026: API update

This update adds five endpoint families, makes plan and permission checks stricter, and aligns several workflows with the Hive3 app.

### New

- **Five new families.** [Search](/developers/api-search), [Broadcasts](/developers/api-broadcasts), [Tickets](/developers/api-tickets), [AI assistant](/developers/api-ai-assistant) and [Credentials](/developers/api-credentials).
- **Eight new scopes.** `broadcasts:read`, `broadcasts:write`, `tickets:read`, `tickets:write`, `ai:read`, `ai:write`, `credentials:read` and `credentials:write`. No existing scope implies them. In the app, Read access adds the four `:read` scopes and Full access adds all eight. See [Scopes](/developers/api-authentication#scopes).
- **`DELETE /api/v1/account/keys/current`.** A key can revoke itself. It needs no scope. See [Data export and key revocation](/developers/api-account-data).
- **Quests in welcome pages.** The welcome-page builder accepts `quests` sections, entries and spotlights, as the app does.

**What to do:** keys created before this update cannot reach the new families. Create a new key with the new scopes to use them.

### Access and plans

- **Honey Bee or above is required.** If the key owner's account is below Honey Bee, every request returns `403` with the code `plan_required`. The key is not revoked and works again after an upgrade. Creating keys and approving CLI logins need Honey Bee or above too.
- **Accounts scheduled for deletion.** Their keys return `401 invalid_api_key` on every route except `DELETE /api/v1/account/deletion`, which still lets the account cancel the deletion. That route skips the plan check only while a deletion is pending. Cancelling now also makes the account searchable again.
- **Moderation scopes.** Deleting someone else's comment, reviewing community applications, removing members and changing roles need `communities:moderate` or `communities:write`, plus a current owner, admin or moderator role. `communities:write` includes `communities:moderate`.
- **Live roles on every call.** Access to another account depends on your role at the time of the request, and on the key's account allowlist if it has one. See [Managed accounts](/developers/api-authentication#managed-accounts).

**What to do:** handle `403 plan_required` and `403 insufficient_scope` without retrying in a loop.

### Reading data

- **Search visibility.** `GET /api/v1/search` lists public and paid-preview items for everyone. Another account's members-only and private items appear only when the key has `communities:read` and its allowlist, if any, includes that account. Each result's `visibility` is the effective value: the item's own setting combined with its account's access type. See [Search](/developers/api-search).
- **List order.** Lists of posts, events, courses, content, quests and jobs are newest first, leave out archived items, and `nextCursor` walks the whole set.

**What to do:** if you search for members-only items, add `communities:read` to the key.

### Creating and changing things

- **Events need approval by default.** Events created through the API default to `autoEnroll: false`. Send `"autoEnroll": true` to accept RSVPs automatically.
- **Moving a world event.** Changing an event's `worldId` removes join links that pointed into the previous world.
- **Quests.** Creating a quest needs `questCreditPlan` (`single` or `bundle`) and spends a quest credit. A missing `endsAt` defaults to 30 days after `startsAt`, so a `single` quest needs an explicit `endsAt` within 7 days. A quest's `subscriptionId` follows the same plan and plan-choice checks as other resources.
- **Archiving is repeatable.** Archiving an already archived resource returns `200`, quests included. It no longer returns `409` for a quest. A quest or event that has started still returns `409`.
- **Event timestamps.** Event slot `startsAt` and `endsAt` must be ISO 8601 with `Z` or an offset, and each end must be after its start.
- **Job application files.** A `url` on a job application must be `http` or `https`; other schemes return `400`.

**What to do:** set `autoEnroll` and `questCreditPlan` explicitly, remove any retry logic that treated a repeated quest archive as a failure, and send timestamps with an offset.

### Participation workflows

- **Attendance.** Recording attendance needs an approved RSVP (`409` otherwise) and an event that is not archived (`404`). The first recorded time is kept, the attendee is notified, and setting `attended: false` on recorded attendance returns `409`.
- **Approvals re-check access.** Accepting an event or course participant who no longer has access returns `403`.
- **RSVP limits.** RSVP changes share the app's budget of 10 per minute and 100 per day, and return `429` with `Retry-After`.

**What to do:** approve RSVPs before recording attendance, and pace RSVP calls.

### Broadcasts and credentials

- **Test sends need a verified email.** `POST /broadcasts/{id}/test` returns `400` until the key owner's primary email is verified. This also applies in the app.
- **Hero images must be `https`.** `heroImageUrl` accepts only `https` URLs through the API.
- **Award limits.** Credential awards are limited per awarding account to 30 requests per minute and 500 people per day, shared with the app. Over a limit returns `429` with `Retry-After`.
- **Uniform `notFound`.** Handles of unknown, private, still-being-set-up, deletion-pending and deleted accounts are all returned in `notFound` alike.

**What to do:** verify your email before testing broadcasts, serve hero images over `https`, and retry awards after the `Retry-After` delay. Do not treat `notFound` as proof that a handle does not exist.

### Rate limits and errors

- **Account budget.** Each account has 600 requests per minute across its keys; the `429` for this budget has no `Retry-After` header.
- **Where `Retry-After` is missing.** It is also absent on post likes, comment edits, deletes and likes, and notification writes. Back off to the next clock minute with jitter.
- **Limits that return `400`.** The per-day and per-item like limits, the shared profile builder save budget, the daily data-export limit and the AI assistant document attach limits return `400 invalid_request` with a message, not `429`.
- **`413`.** A request body larger than a route accepts returns `413` with the code `invalid_request`.

**What to do:** do not rely on `Retry-After` being present; see [Rate limits](/developers/api-conventions#rate-limits).

### Corrections to the documentation

These behaviors were already in place; the documentation now matches them. If your code assumed otherwise, adjust it: expect `404` for other accounts' public resources fetched by ID, parse timestamps by object type, and treat `email` and `resolvedWallet` as personal data.

- Ticket routes are for owners and admins only; moderators cannot manage tickets.
- Reading one event, course, content item, quest or job by ID returns only your own resources or a managed account's (with `communities:read` and the allowlist). Anything else returns `404`, even when it is public in the app. Posts follow normal post visibility.
- Participants, enrollments, evidence, job applications, community applications and members, wallets, linked communities and notification mutes return a plain array with no `page` object, capped as listed in [Pagination](/developers/api-conventions#pagination).
- Posts, events, courses, content, quests and jobs return `createdAt`, `updatedAt` and `archivedAt` as Unix milliseconds. Other objects return ISO 8601 strings. See [Timestamps](/developers/api-conventions#timestamps).
- Participant, enrollment and application lists include each person's `email`, and event participants include `resolvedWallet`. Store and log them as personal data.
- A world event has exactly one slot and an attendee limit of 1 to 500 on the shared Dome, or 1 to 100 in a Royal Hive's own world (the earlier text said 900).
- `Idempotency-Key` is read on resource creates (including posts), `POST /broadcasts` and `POST /ai-assistant/documents`, and remembered for 48 hours.
- The participant list field is `email`, not `primaryEmail`.
- The "must use the account's own plans" rule for subscription access applies to moderators. Owners and admins are not limited to that list.
- `join` and `apply` membership actions behave the same: an open account accepts immediately and a private one records a pending application.
- Data export is limited to 2 per hour and 2 new exports per day.
- AI assistant limits are counted against the key owner, not the account being managed.
- A credential award returns `200`, not `201`.

## CLI 0.4.0

CLI 0.4.0 was published on npm on October 28, 2026. Items in the CLI pages marked "(0.4+)" need this version or later.

### New commands

- **`hive3` is the command name.** The CLI is now called `hive3` everywhere, in the documentation and in its own messages. `hive` also works as a short alias for existing users and runs the same program. Update scripts and agent instructions when convenient; nothing breaks if you do not.
- **`hive3 --version`** (or `-v`) prints the installed version.
- **`hive3 skill`** (`install`, `path`, `show`) installs the Hive3 agent skill that now ships inside the CLI, for Claude Code, Codex, Cursor or any skills directory. The skill is named `hive3`. See [Use Hive3 with AI agents](/developers/cli-agents#install-the-skill).
- `hive3 search`, `hive3 broadcasts`, `hive3 tickets`, `hive3 assistant` and `hive3 credentials`. See [CLI commands: search, broadcasts, assistant, credentials](/developers/cli-commands-areas); tickets moved to [Selling and payments](/developers/cli-commands-payments#tickets) in 0.5.
- `get <id>` for every resource family, `hive3 notifications unread-count`, and `hive3 account linked-communities` with `list` and `disconnect`.
- `--account <id-or-handle>` on profile, builder, broadcast, ticket, assistant and credential commands, to act on an account you own, administer or moderate.
- `hive3 broadcasts update --remove-hero-image`.

### Safer by default

- **Confirmation flags.** `--confirm <exact id>` is required by `hive3 wallets remove`, `hive3 communities remove-member`, `hive3 account linked-communities disconnect` and `hive3 assistant documents delete`. `--yes` is required by `hive3 broadcasts send` and `hive3 credentials award`.
- **Account deletion.** `hive3 account deletion request` is gone. Delete an account in the Hive3 app under Settings. (`hive3 account deletion cancel` was removed in 0.5.)
- **Upload address check.** Before sending a file, `hive3 upload` and `hive3 assistant documents add` refuse an upload address that is not `https` (plain `http` only for a local development server), is not on the API host or a Hive3 storage host, or redirects. No key is sent with the file.
- **Help never runs a command.** `--help` or `-h` after any command prints help, including `logout`, `whoami`, `capabilities`, `login` and `update`. In earlier versions `hive3 logout --help` signed you out.
- **Private config files.** The config file and update cache are written through a private staging directory with mode `0600` and an atomic rename.
- **`hive3 update`** installs exactly the version it reports.
- **`plan_required`.** The CLI now shows a clear message when the account is below Honey Bee.
- **`hive3 logout`** revokes the key on the server through `DELETE /api/v1/account/keys/current` before removing the local file.

**What to do:** run `hive3 skill install --force` if you copied the skill folder by hand earlier, update scripts that used `hive3 account deletion request`, add `--yes` or `--confirm` where the commands above run unattended, and run `hive3 login` again if you need the new scopes. Keep using the same login if you only use existing commands.
